# Permission-query and Windows timeout residuals

## Contract

Issue 41 retains the existing admin-author exemption. This change distinguishes
unavailable or malformed permission evidence from a successful non-admin result,
and removes the assertion that admin authorship proves human review. The identity
policy remains an operator decision. Existing pagination and head-approval rules
are unchanged. GitHub documents the permission response at
<https://docs.github.com/en/rest/collaborators/collaborators#get-repository-permissions-for-a-user>.

Windows shell timeouts and output-buffer overflow must terminate the live shell's
process tree before returning an unsuccessful launch result. No unrelated process
may be terminated. Existing shell quoting, payload bytes, output descriptors,
encoding and synchronous callers remain supported. Direct native launches and
non-Windows execution remain unchanged. Termination failure is a distinct error,
never a claim that cleanup succeeded. This is a helper execution contract, not
protection against an operator or operating system killing the supervisor itself.

## Ownership and transport

Only the Windows real-spawn shell path uses a private Node supervisor. The public
spawnViaShell remains synchronous and existing injected spawn implementations
remain direct test seams. The existing stdin payload file remains an inherited
read descriptor. A private call directory carries configuration and a result;
credentials and environment are inherited rather than serialized there.

The supervisor starts the already-quoted command with asynchronous spawn and
shell:true. It owns the only deadline and output-byte limit. The outer spawnSync
must not receive timeout or maxBuffer and must not pipe supervisor output: either
could kill the supervisor first and orphan its tree. Numeric output descriptors
are inherited into the supervisor at their standard positions and inherited by
the shell. Requested pipe output is collected inside the supervisor, bounded by
the caller's maxBuffer (Node's default when omitted), and returned in the result
as base64. Ignored descriptors remain ignored. No-input pipe stdin is closed.

On timeout or overflow, synchronously invoke the system taskkill executable with /PID, the live
shell PID, /T and /F. The synchronous spawn uses a separate event loop, keeping
the supervisor's shell exit callback and process-handle close pending until the
PID-based utility returns. Do not first call child.kill. A single termination state
prevents repeated kills; cancel the review timer when it begins. Bound taskkill
and pipe closure with a shared cleanup deadline. Timeout maps to ETIMEDOUT;
overflow maps to ENOBUFS. If cleanup fails or cannot complete, return a distinct
ERR_AFK_TREE_CLEANUP error with the initial cause and a diagnostic, never a clean
result. Do not launch a watchdog that can fire after normal exit. On normal shell exit,
replace the review deadline with a bounded drain deadline: descendants can keep
pipe handles open after exit. Drain expiry closes readers and returns
ERR_AFK_TREE_CLEANUP; never invoke taskkill against that exited shell PID.
Timeout cleanup and subsequent draining share one cleanup deadline.

The supervisor writes its result only after success/failure classification and
closes its pipe readers before exit. The parent validates/reads that result and
restores Buffer/string output and Error properties. Supervisor launch failure or
missing/malformed result returns a launch error. Per-call files are removed only
after the result is read. An externally terminated supervisor is an explicit
limitation, not reported as verified descendant cleanup.

## Consumers and scope

Claude and Kimi collect UTF-8 pipes with 64 MiB caps. Relay collects UTF-8 pipes
with a 32 MiB cap and injected-spawn tests. Codex sends stdout and stderr to an
already-open transcript descriptor, with a payload descriptor in design mode and
ignored stdin in diff mode. Preflight calls collect small pipes. Preserve these
shapes; this is not a general-purpose replacement for every spawnSync option.

Allowed implementation: lib/gate/spawn.mjs, one adjacent Windows supervisor,
focused spawn regressions, the existing owner-review-pagination test harness,
require-owner-approval.yml, a scoped Windows validation job, this design and
version 0.9.1 manifests generated by node scripts/sync-marketplace.mjs. Native
Codex verdict syntax, GLM provider behavior, account/token changes, branch policy,
and shipped PR77/PR84 repairs are outside this revision.

## Validation and rollout

Tests precede implementation. Owner fixtures execute the real workflow shell and
cover failing/empty/malformed permission requests, valid non-admin responses,
admin authors, paginated approvals and partial pagination failure. Lookup errors
must be observable before any approval is accepted.

A Windows-only synthetic regression starts a cmd shim, worker and descendant
with readiness/PID files. It observes both child PIDs absent after timeout and
overflow, while an unrelated sentinel survives. A test-owned final cleanup bounds
failed probes. Cover input/no-input, paths with spaces, transcript descriptors,
normal output and timeout/error classification. A scoped Windows Actions job
runs these and existing spawn tests; no credentials or models are involved.
Record live RED against pre-fix production code and GREEN against the final head.
Off-Windows skips do not establish Windows verification.

The first draft PR may contain only the regression/design/job to obtain Windows
RED. Production implementation follows the design critic and that evidence. All
local static checks and focused regressions precede the independent Kimi K3 role.
The final native full suite follows that role. The second cumulative repair cycle is reserved for the consolidated design
corrections. No further automatic review-driven batch remains. Keep the PR open
for owner review.

## Design correction evidence

Node distinguishes process exit from stdio closure in its
[child-process documentation](https://nodejs.org/api/child_process.html#event-exit).
The pinned [Node exit callback](https://raw.githubusercontent.com/nodejs/node/v22.19.0/lib/internal/child_process.js)
closes the process handle, and the
[Windows libuv lifecycle](https://raw.githubusercontent.com/nodejs/node/v22.19.0/deps/uv/src/win/process.c)
releases it in endgame. The
[synchronous-spawn implementation](https://raw.githubusercontent.com/nodejs/node/v22.19.0/src/spawn_sync.cc)
uses a separate loop; synchronous taskkill therefore retains the shell handle
until termination finishes without an extra watchdog. Microsoft documents
[taskkill /T /F](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/taskkill)
as forced process-tree termination. Live tests still supply platform evidence.
